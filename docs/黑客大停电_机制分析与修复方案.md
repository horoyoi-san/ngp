# 西摩「大停电」机制分析与修复方案

> 日期：2026-09-24（第 15 轮）
> 用户原话：「再分析一下西摩的大停电，这个应该是可以触发的，在**一个特定的位置**让全城停电。
> 你分析下他是怎么触发的，能不能帮我修复，游戏能否修复，
> 是在**游戏内触发**还是在**后台添加一个按钮**触发。详细进行分析」

---

## 0. 一句话结论

**大停电 = 黑客（西摩）的「俄罗斯方块」小游戏**。玩完之后生成一个半径 100 的
「【黑客】大停电-范围干扰」**创造物**。

但 —— **「全城停电」的画面不在创造物里，而在客户端的一个 Spoon 剧情节点里**
（节点上配了「灯光替换特效」+「扩张关灯盒」）。
⇒ **服务端没有任何一条 S2C 能让客户端播停电演出**。

| 问题 | 答案 |
|---|---|
| 怎么触发的？ | 天赋 `99906106` → 骇入**电网** → **Spoon 节点 `PlayHackerTetrisNode`** → 小游戏 → 创造物 `56860922` |
| 游戏内能触发吗？ | **能**，但前提是客户端 **Spoon 图跑到那个节点**。私服没做任务/剧情链 ⇒ 节点不会被执行 |
| 后台按钮能触发吗？ | **能，但只能做两件事**：① 补前置条件（天赋 + 能力 buff）；② 生成创造物。**不能播演出** |
| 游戏能否修复？ | 「范围干扰」的**游戏效果**可以修（已实现）；「全城停电」的**视觉演出**需要客户端 Spoon 图配合 |

## 1. 它到底是什么 —— `HackerConfig.static.json` 里的整套参数

之前只看到「俄罗斯方块」四个字，这次把 `HackerConfig.static.json` 的**扁平字段**全列出来
（注意：这张表不是 `records` 形式，是**扁平 dict**，用 `records` 解析会 `KeyError`）：

| 字段 | 值 | 含义 |
|---|---|---|
| `HackerTetris_PlayTime` | **60** | 小游戏时长（秒）—— 对应天赋描述的「1分钟的大停电」 |
| `HackerTetris_DropLimit` | 50 | 下落次数上限 |
| `HackerTetris_ClearPoints1..4` | 100 / 400 / 800 / 1600 | 消 1/2/3/4 行的得分 |
| `HackerTetris_DefaultGravity` | 3 | 初始下落速度 |
| `HackerTetris_GravityCoefficient` | 0.1 | 每消一行的加速系数 |
| `HackerTetris_ActionStatus` | 156 | 玩家动作状态 id（玩方块时的姿态） |
| `HackerTetris_OnceDropCountLimit` | 5000 | 单次下落计分上限 |
| **`HackerTetris_CreationId`** | **56860922** | ★ 结束时生成的创造物 |
| **`HackerTetris_Range`** | **100** | ★ 作用半径 |
| `HackerTetris_CreationId_Dark` / `_Light` | `[56860922]` | 暗/亮两个版本，**都是它** |

配套配置：`CreationConfig.Id = 56860922`「【黑客】大停电-范围干扰」
（字段只有 `Id / Name / Time=0.3 / NeedPreLoad=false / EnvironmentKill*`）。

## 2. ★ 怎么触发的 —— 完整链路

### 2.1 前置：天赋三件套

`TalentTreeTalentConfig`（全部 425 条天赋的 `StartVersion` 都是 `V99.0.0`，
是**全局占位版本号**，不代表未实装）：

| Id | 名称 | 描述 | 关键字段 |
|---|---|---|---|
| **99906106** | **大停电** | 「可以骇入**电网**造成1分钟的大停电，使周围行人陷入恐慌，敌人感知与行动能力大幅下降一段时间」 | `JobRequest=401`、`NeedActive=true`、`PreTalentIds=[99906204]`、`LayerNum=1`、`TalentTreeid=[99900010]`、`CostPoint=1`、`Buff=[]`、`IconId=28003498` |
| 99906107 | 游戏植入 | 「触发大停电后，于**千集条商业街的入口**可骇入其广告屏，进行游戏游玩」 | 同上 |
| 99906108 | 大停电强化 | 「大停电的持续时间增加 30 秒」 | 同上 |

> ★ `99906107` 的描述直接印证了用户说的「在**一个特定的位置**」——
> 那个位置是**千集条商业街的入口**。
>
> ★ `99906106` 的 `Buff = []`、`InitActiveGameplayIds = []` —— **天赋本身不带任何 buff**，
> 所以能力不通过天赋下发，而是走 `HackerMenuConfig` / 小游戏流程。

### 2.2 触发链（逐环都有据）

```
① 天赋 TalentTreeTalentConfig.Id = 99906106「大停电」
     JobRequest = 401（职业黑客）、NeedActive = true、LayerNum = 1
   ↓
② 骇入**电网**对象（世界里一个特定的位置）
   ↓
③ ★★ Spoon 剧情节点 `PlayHackerTetrisNode` 执行 `DoAction()`
     类：`L50.Spoon.SpoonRunTime.PlayHackerTetrisNode : SpoonClientNode`
     序列化标记：`[SpoonSerializerData(1932)]`
     ┌─ 节点字段（dump 原文）────────────────────────────────────────┐
     │ [FieldIndex(6)]  SpoonNodeArrayFieldValue<ulong>  replaceEffectIds   │ ← 停电特效替换
     │ [FieldIndex(7)]  SpoonNodeArrayFieldValue<string> replaceEffectNames │
     │ [FieldIndex(12)] SpoonNodeField<int>  lookAtPivotId                  │ ← 定位点（"特定的位置"）
     │ [FieldIndex(13)] SpoonNodeField<int>  expandingLightDisableBoxId     │ ← ★ 扩张关灯盒
     │ private ExpandingLightDisableBox expandingLightBox;                  │
     └──────────────────────────────────────────────────────────────────────┘
     对应编辑器版本：`PlayHackerTetris : SpoonClientAction`（TypeDefIndex 38865）
     ↓
④ 小游戏 UI（客户端 Lua）→ `AskStartHackerTetris`(63521495) → 服务端回 `uint`
   ↓
⑤ 玩完 → `AskFinishHackerTetris`(63554976, `score`)
   ↓
⑥ `ReportHackerTetrisCreation`(67652382)
   ↓
⑦ 生成 Creation `56860922`，半径 `HackerTetris_Range = 100`
```

## 3. ☠️ 为什么服务端"修不了视觉"

### 3.1 演出在 Spoon 节点里，不在创造物里

| 视觉 | 载体 |
|---|---|
| 灯光**替换**成停电特效 | `PlayHackerTetrisNode.replaceEffectIds` / `replaceEffectNames`（节点上配的**资产引用**） |
| 灭灯**扩散**（一片片黑下去 = "全城停电"） | `ExpandingLightDisableBox`（节点用 `ComponentLinkId("expandingLightDisableBoxId")` **绑定的场景对象**） |
| 镜头朝向 | `lookAtPivotId`（`ComponentLinkId("lookAtPivotId")`） |

创造物 `56860922` 的 `CreationConfig` 里**只有** `Id / Name / Time / NeedPreLoad / EnvironmentKill*`
—— 没有任何灯光/演出字段。它提供的是**游戏效果**（范围干扰：敌人感知与行动能力下降）。

**⇒ 服务端翻遍了 RPC 表，没有一条能驱动灯光/环境/停电**（见 §3.3）。

### 3.2 Spoon 节点的实现拿不到

`PlayHackerTetrisNode.DoAction()` 的 RVA `0x122FC1D0` 旁边有
`<>iFixBaseProxy_DoAction` —— 说明它被 **IFix 打过补丁**，
**方法体不在 `GameAssembly.dll` 里，而在 Lua 补丁里**。
CBT3 的客户端 Lua 是加密 bundle（项目只有 CBT2 的转储，而 CBT2 的 Lua 里
**完全搜不到 `Tetris`**）⇒ 这条路取证不到。

### 3.3 相关 RPC 的实测结论

| 方法 | id | 通道 | 说明 |
|---|---|---|---|
| `AskStartHackerTetris` | 63521495 | C2S Invoke → `uint` | ✅ 已实现（回 1） |
| `AskFinishHackerTetris` | 63554976 | C2S Invoke | ✅ 已实现 |
| `ReportHackerTetrisCreation` | 67652382 | C2S **Notify** | ✅ 已实现 |
| `SyncAddCreation` | 68413195 | S2C，`LuaAndCSharp` | ✅ **客户端实现了**（`ReadStruct(Auto.Reader[425])`） |
| `SyncActiveSpiritJobTalentLayer` | 64444711 | S2C，`LuaOnly` | ✅ 客户端有 reader |
| `SyncUnitAddBuff` | 68596304 | S2C | ✅ 已在用 |
| ~~`SyncVehicleHackableState`~~ | ~~68037721~~ | —— | ❌ 无 C# 实现（第 10 轮教训） |
| **灯光/环境/停电类 S2C** | —— | —— | ☠️ **一条都没有** |

`GmAddCreation`(69648023) / `GmAddCreation2`(69725627) 在客户端**没有 reader**
⇒ 不能用它们。

## 4. 服务端能做的三件事（已实现）

### 4.1 补前置条件

```
SyncActiveSpiritJobTalentLayer(64444711)
  = spiritId:u32, jobClassId:u32, talentId:u32, layer:u32
  → spiritId=当前角色, jobClassId=401, talentId=99906106, layer=1

SyncUnitAddBuff(68596304)
  = BuffConfig.Id 52606170「黑客-俄罗斯方块大停电能力」（IsHidden / Duration=-1 / DeadKeep）
```

补齐后，**只要客户端跑到那个 Spoon 节点**，链路就能通。

### 4.2 直接生成创造物

```
SyncAddCreation(68413195) = Base.ReadStruct(Auto.Reader[425])
```

`Auto.Reader[425]`（`UX.Game.CreationInfo`）**12 个字段**：

```
Id:u64, ParentId:u64, TargetId:u64, DestructibleId:u64, CreationId:u32,
ParentPosition:UXVector3(Struct,无标记), Rotate:f32, ClientEnterOrLeave:bool,
SourceSkillId:u32, SourceDestructibleId:u64, GadgetId:u64, GadgetTransformId:i32
```

⚠️ 客户端用 `Base.ReadStruct` 读 ⇒ **无对象标记** ⇒ 契约必须 `[UxContract(Inline = true)]`，
否则多写一个 `0xFF` 整包错位。

### 4.3 触发入口的结论（第 13 轮已定案，本轮复核）

`HackerMenuConfig.Id = 4`「大停电」是一行**空壳**：

```json
{"Id": 4, "MenuType": 0, "Title": "大停电", "Description": "",
 "Image": 0, "FuncAction": "", "PanelId": 0, "GuideId": "", "BuffID": 0}
```

对比同表其它行：

```json
{"Id": 1, "Title": "EonBug Forum", "FuncAction": "CheckShowPanel()", "Image": 28003912, "BuffID": 0}
{"Id": 2, "Title": "Spider Bot",   "FuncAction": "SpiderSkill()",     "Image": 28002972, "BuffID": 52606149}
{"Id": 3, "Title": "Hacker Drone", "FuncAction": "DroneSkill()",      "Image": 28002971, "BuffID": 52606150}
```

⇒ 大停电那一行 **`FuncAction` 是空串、`BuffID = 0`、`Image = 0`、`GuideId = ""`**
—— 连图标都没有。`HackAction.RunFunc("")` 里 `load("")` 得到空函数体 ⇒ **点了什么都不发生**。
而且**菜单是客户端配置**，服务端加不了条目。

## 7. 边界（明确做不到的）

1. **停电演出**：需要客户端 Spoon 图跑到 `PlayHackerTetrisNode`。私服没有任务/剧情链驱动，
   节点不会被执行 ⇒ 服务端无法单独实现。
2. **小游戏 UI**：`PlayHackerTetrisNode.DoAction()` 是 IFix 补丁，逻辑在 Lua 里；
   CBT3 的客户端 Lua 拿不到，CBT2 的 Lua 里没有 Tetris ⇒ **无法离线复刻小游戏 UI**。
3. **App 按钮**：`HackerMenuConfig.Id=4` 是空壳行且属客户端配置 ⇒ 加不了。
4. **电网对象**：`CreationConfig.Id = 56980107`「关卡电网creation」存在，但
   **世界里的电网实体由关卡/场景数据摆放**，私服不生成关卡 ⇒ 没有可骇的电网。
5. 创造物 `56860922` 生成后**是否真的产生"范围干扰"效果**需要实机验证 ——
   它的 `CreationConfig` 只有 `Id/Name/Time`，效果可能也在客户端 prefab 里。

## 8. 建议的验证顺序

1. 先 `POST {"action":"prerequisites"}` → 看客户端天赋页/能力是否变化（日志会打 `[BLACKOUT]`）。
2. 再 `POST {"action":"spawn"}` → 看**角色脚下**是否出现创造物（`SyncAddCreation` 已发）。
3. 若都没反应，说明这两条也依赖客户端上下文（例如需要先开天赋树面板），
   那就只剩「客户端 Spoon 图」这一条路 —— 需要补任务/剧情链才能触发。

### ☠️ 两个容易误判的点

1. **面板 HTML 读磁盘副本，改完不用重编译**；但**服务端没跑时 5809 返回 `502 Bad Gateway`**
   （不是 404），看起来像"面板没生效"，其实是服务端停了。
2. **没有客户端在游戏里时，POST 会回 `{"ok":false,"error":"客户端不在游戏中（没有活动会话）"}`** ——
   这是正常的（`hub.Current` 为空），不是 bug。

**「全城停电」的视觉演出**（见 §3）。按钮只能做到「补前置条件 + 生成创造物」，
真正的灭灯演出在客户端 Spoon 节点 `PlayHackerTetrisNode` 里（`replaceEffectIds` +
`ExpandingLightDisableBox`），服务端发不出。
