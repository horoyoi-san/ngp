# 任务列表（任务 / Mission 面板）一直空白的根因分析与修复

> 排查日期：2026-09-23 · build 4229938 · 私服 `Ananta.Server`
> 结论先说：**面板列表渲染的是「任务事件」(`TaskEventConfig.EventName`)，而私服从来没下发过任何事件。**
> 不是编码错、不是反序列化失败、也不是任务容器没发 —— 容器一直发得好好的，缺的是**另一个字段**。

## 5. 为什么图三（地图）有图标，图二（列表）没有？

地图图标和面板列表走的是**两套数据**：

| | 数据来源 | 状态 |
|---|---|---|
| 地图图标 / 地图右侧任务筛选列表 | 客户端**本地** `TaskEventConfig`（1688 条，带 `SMapPhoto` / `CenterPos` / `BlockId` / `Tag`） | ✅ 正常（图三） |
| 任务面板列表区 | 服务端下发的 `EventPanelInfo.EventsInfo` → `m_TaskEvents` | ❌ 恒空（图二） |

例：事件 1466「巴迪一家的新成员」带 `SMapPhoto: 28017589`、`CenterPos: [875.54, -0.11, 2154.57]`、`BlockId: 1`
—— 这些字段就是地图图标的来源，**和面板列表无关**。

> 这正好解释了用户的原话：「任务在地图上会有图标，看图三」但列表空白。

## 8. 已实施的修复

### 8.1 新增：`Ananta.Core/ClientData/Client4229938/TaskEventCatalogRepository.cs`

读 `TaskEventConfig.json`，提供：

* `TryGet(eventId)` / `AllEventIds()` / `Search(term)`
* `EventsForTask(taskId)` —— 任务 → 所属事件
* `TasksOf(eventId)` —— 事件的任务链

**关键点：任务 id 不连续，所以"事件包含哪些任务"不能用 `[StartTask, EndTask]` 区间判断，
必须沿 `TaskConfig.NextTasks` 走链**，遇到 `EndTask` 收尾（含）。
实测事件 1441「天生救世主」链 = `60004938 → 60004939 → 60004941 → 60004943 → 60004942 → 60004950 → … → 60004953 → 60004955`，正好收在 `EndTask=[60004955]`。✅

### 8.2 修改：`GameRouter.Quests.BuildTaskContainer()` 填 `EventsInfo`

新增 `BuildEventPanelInfo(state)`：

1. `autoDeriveEvents`（默认开）：容器里每个任务 → `EventsForTask` → 得到候选事件集合；
2. 再并入配置里的 `eventIds`；
3. 每个事件取**其任务链里第一个"容器中确实有"的任务**作为 `TaskId`（可用
   `eventTaskIdFollowsContainer=false` 改成固定填 `StartTask`）；
4. `StatusData = quests.eventStatusFlags`（默认 `21 = Visible|HasAccepted|IsUnderway`），
   `UnlockTime = 当前 Unix 秒`，`FinishedChoiceLs = []`。

`PushTaskContainerAsync` 现在会打：

```
[QUEST] SyncPlayerAllTask tasks=N current=X events=M loginGameServer=true
[QUEST][EVENT] event=1441 '天生救世主' task=60004938 status=21
```

### 8.3 新增配置项（`gameplay.quests`）

```json
"eventIds": [],                        // 额外指定要显示的事件（留空=只靠推导）
"autoDeriveEvents": true,              // 从任务容器自动推导事件
"eventStatusFlags": 21,                // Visible(1)|HasAccepted(4)|IsUnderway(16)
"eventTaskIdFollowsContainer": true    // TaskId 跟随容器；false = 固定填 StartTask
```

### 8.4 新增：`TaskEventConfig.json` 进服务端配置目录

`ConfigDump_v3/TaskEventConfig.json` → `Ananta.Server/ClientData/4229938/Configs/TaskEventConfig.json`（3.3 MB）。
以前服务端**只读 `TaskConfig.json`**，没有事件表。

### 8.5 新增：调试面板 `GET /api/dict/events`

返回全部 1688 个事件的 `{id, zh, en, startTask, endTasks, chapter, sort, tag}`，
方便挑 `eventIds`。

## 11. 遗留 / 未解决

* **Spoon 图**（第 6 节）：`GameRes/Spoon/HotRaid/<名字>.rcp` 与
  `GameRes/Spoon/Task/SpoonTask{raid}_{alias}.tcp` 都不在本地资源里。
  客户端 `SpoonRaidMgr` 有一套补丁注册表（`RegisterPatch` / `TryGetPatchBytes` / `HotUpdate`），
  理论上可以喂字节，但需要先确认 `ClientGraphType` 取值与格式 —— 上一轮的
  `tools/SpoonDumper/SpoonDiagPlugin.cs` 就是为这个写的（目前 `plugins/` 是空的）。
* `sceneSpoonNames: ["Xinshouben"]` 仍是推断值。当前 raid 是 23300888「Nova City」，
  而 `Xinshouben` 是 raid 23301180（序章）的资产前缀 —— **名字和当前场景本身就对不上**，
  这会让 `LoadSpoon` 必然失败。要么改成当前 raid 的真名，要么置空。
* 增量事件同步（`SyncEventPanelView` / `SyncDeleteEventPanelView`）没做 —— 现在靠整包重推。
* `EventsInfo` 里没有填 `EventViewInfoList`（`EventSpoonViewInfo` 需要 raid + md5，
  同样卡在 Spoon 资源上）。
