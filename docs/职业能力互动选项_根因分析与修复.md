## 1. 注册日期 1970 —— `RegisterTime` 是 Unix 秒

客户端三处都用它格式化：

```lua
-- DeliveryAppPanelStore / DeliveryAPPBeginPanelStore / PolicePanelManager
local registerTime = os.date("%Y.%m.%d", spiritJob.RegisterTime)
```

以前 `BuildSpiritJob4229938` 写死 `RegisterTime = 1` ⇒ `1970.01.01`。

修法：`RuntimePayloadFactory.JobRegisterTime4229938(spiritId, jobId)` ——
第一次赋值时写进存档 `PlayerState.SpiritJobRegisterTime`（`spiritId → jobId → 秒`），
之后一直复用，保证同一账号日期稳定（不会每次登录都变）。

实测：`reg=1790151077 → 2026.09.23`。

## 2. 物流 App 停在「前往入职培训」—— 缺 `SubmitEventList`

### 客户端逻辑（`LX6/ScriptFunc/MainPhoneFunctionAction.lua:OpenUberSim`）

```lua

    local teachEventId = LTConfig.UberSimConfig.TeachEventId          -- = 1234
    local eventState = gTaskManager:GetTaskEventState(teachEventId)
    args.eventSubmited = eventState == UX.Game.TaskEventState.Submited
    args.eventDoing = false
    if not args.eventSubmited then
        local nowDoingTask = gTaskNodeManager:GetNowDoingTask()
        if nowDoingTask and nowDoingTask > 0 then
            args.eventDoing = gTaskNodeManager:GetEventIdByTask(nowDoingTask) == teachEventId
        end
    end

    if (args.eventSubmited or args.eventDoing) and 职业大类 == Delivery then
        -- ★ 正常路径：拉订单 → 显示【订单】页
        AskGetTruckJobOrders().Callback = function (errorId, clientTruckOrderView)
            args.secondShowType = DELIVERY_APP_SHOW_TYPE.ORDER

            gMainPhoneUtils.ShowPhoneAppContent(args)
        end

        -- 引导路径：「前往入职培训」卡片
        args.showType = MAIN_PHONE_ROOT_SHOW_TYPE.DeliveryApp

    end
end
```

`DeliveryAPPBeginPanelStore:InitView` 里 `guideCtrl = not eventSubmited and not eventDoing and 1 or 0`
—— 同一份判据。

### `GetTaskEventState` 只认 `taskSubmitEvents`

```lua
function M:GetTaskEventState(id)
    if self.taskSubmitEvents[id] then return TaskEventState.Submited end   -- ★ 第一句
    local taskInfo = self.taskEvents[id]
```

`taskSubmitEvents` ← `EventPanelInfo.SubmitEventList`（`SyncPlayerAllTask` 的第 4 个参数）。
**私服从来没填过这个字段**（只填 `EventsInfo`）。

新增 `QuestSettings.SubmitEventIds`（默认 `[1234]`），
`GameRouter.Quests.BuildEventPanelInfo` 把它写进 `panel.SubmitEventList`。

```json
"quests": { "submitEventIds": [1234] }
```

事件 1234 = `TaskEventConfig` 的 **「滴水不漏 / Watertight」**（Cat Express 新人培训），
`StartTask 60017505` / `EndTask [60017512]` / `Preconditions [611]` /
`UnacceptGpsPostion [1770.69, 0, 1258.14]`。

## 3. 点「前往入职培训」只退出不导航

`DeliveryAPPBeginPanelStore:OnTaskAcceptBtnClick`：

```lua
function M:OnTaskAcceptBtnClick()
    local gpsId = gMapSubSystem_Task:GetGpsIdByTaskEventId(UberSimConfig.TeachEventId)
    if gpsId then
        gMapUtils:PlayerOpenBigMap({ autoSelectGpsId = gpsId })
    end
    self:OnExit()          -- ← 「点击后 app 就退出了」是**设计行为**
end
```

`GetGpsIdByTaskEventId` 从 `MapSubSystem_Task.unacceptTask[eventId]` 或
已接任务的 map element 里取 gpsId。事件 1234 没激活 ⇒ 两边都没有 ⇒ 返回 nil ⇒
**只退出 App、不打开地图**。

修完 §2 之后这条路径基本不会再走到（App 直接进订单页）。
真要让"前往入职培训"也能导航，需要把事件 1234 作为
`EventsInfo` 里 `Visible|Acceptable` 的事件下发，让客户端为它建出地图元素
——但那需要 `TaskTitleConfig` / `TaskConfig` 链路都通，本轮没做。

## 4. 订单列表 —— 中性模板打补丁（本轮的主要工程）

### 4.1 为什么不能自己拼结构

`TruckJobOrderWrap`（客户端 reader 286）的字段表**不在任何 dump 里**：
IL2CPP metadata 里是空类（`base/il2cpp.h` 的 `_Fields {}` 也是空的），
形状串又被生成器截断。照 CBT2 抄也不行 —— CBT3 把它内部的 `TruckPosInfo` 从
5 字段改成了 7 字段。

### 4.2 但中性包能用

`DefaultReturnCatalog4229938` 里 `AskAcceptTruckJobOrder`(63110537) 的中性字节
= **一个完整的 `TruckJobOrderWrap`（259 B，全 0 实例）**。字段数天然正确。

### 4.4 做法

`Ananta.Server/Ananta.Core/Protocol/Client4229938/TruckOrderCodec4229938.cs`：

- 启动时从 `DefaultReturnCatalog4229938` 取模板，并**校验标记偏移**，不一致就抛异常
  （宁可起不来也不要发错包）；
- `BuildOrder(...)` 克隆模板 → 只写上面表里的偏移；
- `BuildOrderViewBytes(orders, ...)` 用**字节**拼 `ClientTruckOrderView`
  （因为 `TruckJobOrderWrap` 在我们这边是空类，`UxSerializer` 表达不了）。

自检（`--probe-jobability`）：

## 5. ★★ 为什么里希的盘查 / 审讯修不了（Spoon 图）

### 客户端入口（`182_LX6_Manager_GamePlay_PoliceJob_PoliceJobManager.lua`）

```lua
local data = {
    calledInSpoon = true,          -- ★ 明确标记"由 Spoon 调用"
    targetPid = targetPid,
    customFines = customFinesTable,
    customOptions = customOptionsTable,
    useCustomDialogs = useCustomDialogs,
    guideOptions = guideOptionsTable,
    askDialogId = askDialogId,
    ...
}
if gGameSwitch.EnablePoliceJobStoryLegacy then
    gPoliceJobManager.examineMgr:PrepareDataFromSpoon_Story(data)
else
    gPoliceJobManager.examineMgr:EnterPoliceExamine(data)
end
```

⇒ **盘查/审讯的"目标 + 可用选项 + 罚款项 + 对话"全部由 Spoon 图节点传进来**
（`EnterPoliceExamineBySpoon(targetPid, customFines, customOptions, ...)`）。
没有 Spoon 图 ⇒ 客户端永远不会进入 examine 状态 ⇒ 互动菜单里当然没有那些选项。

`PoliceConfig` 里那 16 个选项（Inquiry / Command / ID Check / Frisk / Alcohol Test /
Drug Test / Issue Citation / Arrest / Release / …）`JobId` 都是 `[]`（不按职业门控），
所以它们**不是**被配置挡住的 —— 是**没人触发进入 examine**。

### 为什么 Spoon 图没有

`GameRes/Spoon/**` 是**热更新（patch CDN）资源**，两个 CBT 的随包资源里都没有
（详见 `notes/quest-events.md` §「第二轮：Spoon 图确实不在随包资源里」，
扫 597,699 条目零命中）。**这不是服务端能修的。**

### CBT3 的警察系统还被裁过

| 类型 | CBT2 | CBT3 |
|---|---|---|
| `SpiritPoliceJobInfo` / `PoliceCaseInfo` / `PoliceViolationInfo` / `PoliceDispatchInfo` / `PoliceDutyBasicInfo` | 有 | **全部不存在**（`dump.cs` / `base/il2cpp.h` 里搜不到） |
| `PlayerInfoPolice`（含 DispatchInfos / ViolationInfos / CaseInfos / DutyBasicInfo / EscortedNpcs / PoliceFakeFileInfo） | 有 | 不存在 |
| `PlayerClientInfoPolice` | —— | 只剩 `TodayCompleteMissionCnt` 一个字段 |
| `PoliceFakeFileInfo` / `PoliceFakeClueAgentInfo` / `PoliceRPSCardInfo` | 有 | 有 |

⇒ CBT3 的警察**数据模型**大幅缩水，说明这一块在 CBT3 里本来就被砍到只剩
"任务链 + 伪人档案"。

## 6. ☠️ 西摩的骇入互动 —— **也是 Spoon / 场景物件驱动，服务端修不了**

### 6.1 第一版结论错了一半（已修正）

第一版看到的是会话日志里这行：

```
[JOBABILITY][HACK] 没有街边 NPC，跳过 SyncUnitHackableState
```

于是判断「服务端一个单位都没有 ⇒ `SyncUnitHackableState` 无目标 ⇒ 骇入选项不出现」，
并加了「自动投放市民」的逻辑。

**用户指出「现在是有 NPC 的」** —— 世界里的 NPC 是**客户端 Aether 人群**
（客户端 Mass AI 从 `ClientCrowdInitData` 生成），**服务端根本不跟踪**；
`PlayerState.StreetNpcs`（服务端手动放置的那份清单）为空 ≠ 世界里没 NPC。
⇒ **自动投放是多余的，已按要求删除**（连同 `autoSpawnHackTargets` /
`hackTargetCount` / `hackTargetDistance` 三个配置项与 `EnsureHackTargetsAsync`）。

### 6.2 骇入互动真正的驱动方（定案）

| 环节 | 位置 | 说明 |
|---|---|---|
| 注册骇入互动 | `L50.Spoon.SpoonRunTime.SpoonGadgetManager.RegisterHackInteract(ulong key, HackInteractRegisterParams param)`（`dump.cs:781876`） | **Spoon 运行时节点**；参数 `HackInteractRegisterParams { HackerId(0x50), InteractType(0x58) }`（TypeDefIndex 19359） |
| Lua 侧读什么 | `gGadgetManager.HackInteractTarget`（`LX6/SGUI/StoreDefine/UniqueSkillHackStore.lua:111/121/140/151/181`）+ `L50.L50App.Scene.HackManager:GetUnitHackBtns(unit)` | 只有 `HackInteractTarget` 非 nil 时才显示骇入按钮 |
| 场景物件（机关） | `HackingSCIIConfig`（**71 行**：紧锁的大门 / 机关锁 / 基地大门 / 密闭的小门 …） | 每条带 `InteractionLabel`（「尝试侵入」「解开门锁」）、`InteractionPreFunction`（`UnlockTrigger()`）、`EnableFightHack`、`NearHack{isNeedNear,distance}` |
| 机关名单 | `HackerHackJiguanConfig`（56 行：Camera / Laptop / Desktop / Treadmill / Vending machine …） | 纯展示（Icon / Name / Introduction） |
| NPC 名单 | `HackerHackNpcConfig`（96 行：Shota / Ken / Matthew …） | 纯展示（Name / Icon / Job） |
| 单位侧标记 | `AgentData.CanBeHacked`（`dump.cs:5081842`）、`VehicleComponent.IsHackable`（`dump.cs:3424231`） | **客户端本地字段**，由 Spoon 节点 / 关卡数据设置 |

### 6.3 决定性证据：`SyncUnitHackableState` 不是那条链路的输入

CBT2 全量 lua 里搜 **`SyncUnitHackableState` / `CanBeHacked` / `IsHackable` 三个词 → 零命中**；
骇入按钮只看 `gGadgetManager.HackInteractTarget`，而 `HackInteractTarget` 由
`SpoonGadgetManager.RegisterHackInteract` 设置。
⇒ Spoon 图不在随包资源里 ⇒ **骇入互动服务端修不了**。

### 6.4 现在保留了什么

`PushHackableUnitsAsync` 还在（把服务端已知的街边 NPC + 已召唤车辆发一遍
`SyncUnitHackableState`），理由：它是本 build 里**唯一**有处理器的骇入 S2C，
万一 CBT3 的 lua 确实吃它，发了无害。代码注释里已写清「它不是那条链路的开关，
别再往这条路上花时间」。`markVehiclesHackable` 可单独关车辆部分。

`AskHack` / `AskHackVehicle` / `AskStartHackerTetris` / `AskFinishHackerTetris` /
`AskVehicleStartHackerAutonomousDriving` / `AskHackerBetray` / `ReportBeHacked` /
`ReportHackerTetrisCreation` 的处理器都保留 —— 客户端一旦真的能触发骇入，
这些 C2S 会被接住并回包（不会再出现「点了没反应」）。

### 顺带接住 `AskInteractCmd`

用户一局里客户端发了 **215 次** `AskInteractCmd`(67390408)（+ `AskInteractCmds` 67088502），
以前全落进 `DefaultUnknownNotify4229938` 只打一行 `unimplemented notify`。
现在显式注册并记录长度，方便后续判断"客户端到底想交互什么"。

`InteractCmdData`（struct，TypeDefIndex 32475）：
`CmdType(u32) / sender(u64) / receiver(u64) / broadCastType(i32) /
 CommandData(byte[], 前置 1 字节非 0 标记 + int32 长度) / CommandDataLen(i32) /
 stringParam1 / stringParam2`。
