## 1. 黑客职业系统 —— 三条根因

### 1.1 ★★★ `EnableHack = false`（头号根因）

私服在 `GameRouter.Aether.cs` 的**三处** NPC 生成点全部写死：

```csharp
EnableHack = false,
```

**为什么这一个布尔就是开关**：

- `EnableHack` 在 CBT2/CBT3 的**游戏 lua 里零引用** —— 全量搜只命中
  `RPCDeserializeAuto.lua` 的 `obj.EnableHack = reader:ReadBoolean()`。
  也就是说它被读进 C# 对象后由**原生 Aether 代码**消费，决定这个单位
  能不能挂上骇入互动。
- 参考实现（CBT2 `AnantaTestGameServer/server/Ananta.Handlers/Game/ClientToGameserver.SaimoHack.cs`）
  专门投放**一个** `EnableHack = true` 的测试 NPC 才能让骇入可用 ——
  `SpawnSaimoHackTestNpc()` 里写得很直白：
  ```csharp
  EnableHack = true,
  AgentSyncClientInfo = new AgentSyncClientInfo {
      CanBeExaminedByPolice = true, ...
  }
  ```
  反过来证明这个字段就是开关。
- 世界里的 NPC 是**客户端 Aether 人群**，但它们的所有权/属性来自服务端下发的
  `ClientStaticNpcInitData` ⇒ 服务端说 `false`，客户端就一个都不给骇。

**修法**：新增 `spiritContent.hackTargetsEnabled`（默认 `true`），
三处生成点改读 `GameRouter.HackTargetsEnabled`。

> `GameRouter.SwitchTimeline.cs` 的**演出同伴**保持 `false`（那是换人过场临时单位，
> 让它可骇入只会在过场里冒出骇入按钮），已加注释说明。

### 1.2 ★★★ 从不下发骇入电量

客户端 `29_LX6_Gadget_GadgetManager.lua:1987`：

```lua
function M:AskHack(index, cb)
    ...
    local cfg = LTConfig.HackerHackTypeConfig.GetConfig(id)
    if Mathf.Floor(gInteractionManager.hackInfo.BatteryCurrentCount) < cfg.HackCost then
        return false          -- ← 只播"电量不足"动画，AskHack 根本不发出去
    end
    gClientToGameDelegate:AskHack(id).Callback = ...
    return true
end
```

`gInteractionManager.hackInfo` 的**唯一**赋值处（CBT2 `1206_LX6_Service_GameToClientImpl.lua:510`）：

```lua
function GameToClientImpl.SyncHackerBatteryCurrentAndTotalCount(hackInfo)
    gInteractionManager.hackInfo = hackInfo
    gMessageManager:SendMessage(gEventConstants.HACK_BATTERY_CHANGE, hackInfo)
end
```

⇒ **私服从不下发它** ⇒ `hackInfo` 是 nil ⇒ 读 `BatteryCurrentCount` 直接抛 lua 错误
（或按 0 算）⇒ 每一次点骇入都在客户端本地被拦下。

**线格式取证**（`Ananta.Proxy/proxy/lua/RPCDeserializeAuto.lua`）：

```lua
-- 3688 行
self.midToReader[64742857] = function (reader)
    return Base.ReadComplex(reader, Auto.Reader[362])   -- 先读 1 字节非空标记
end
-- 27853 行
Auto.Reader[362] = function (reader, obj)
    obj.BatteryTotalCount   = reader:ReadUInt32()
    obj.BatteryCurrentCount = reader:ReadUInt32()
end
```

⇒ **`FF` + `TotalCount(u32)` + `CurrentCount(u32)` = 9 字节**。

**修法**：`GameRouter.PushHackerBatteryAsync()` 发 6/6
（与 `HackerConfig.HackBatteryCount`、参考实现一致）；
接进基线 `jobability` 步骤 + `AskSwitchSpiritComplete`。

### 1.3 骇入三件套处理器没注册

| `AskHackingNpcPress` | 67747341 | `instanceid(u64)` | ❌ 未注册 |

| `AskFinishHackingKeyFrame` | 67159381 | `id(u32)` | ❌ 未注册 |

## 3. ☠️ 逮捕（盘查）职业系统 —— 本 build 服务端**没有入口**

### 3.1 本 build 根本没有盘查的 C2S

用本 build 的方法名表反查（这是判定"某方法在本 build 存不存在"的标准动作）：

```bash
cd Ananta.Proxy/proxy/lua
for id in 63233964 63371802 63398162 63445929 63548238 63598566 63674017; do
  grep -oE "midToName\[$id\] = \"[A-Za-z0-9_]+\"" RPCMethodIdToName.lua || echo "$id 不存在"
done
```

结果：**7 个全部不存在**。`ClientData/4229938/MethodId.dump.cs` 与 `MethodIds.json` 里也没有。

⇒ `AskPolicePrepareExam` / `AskPoliceExamInteract` / `AskPoliceExitEscortOrExam` /
`ReportPoliceExamCommandEnd` / `AskPoliceFineNpc` / `AskPolicePrepareEscort` /
`AskPoliceEscortNpc` **在 CBT3 被整体砍掉了**。
（`Ananta.Core/.../MethodId.cs` 里那 7 个常量是上一轮从 CBT2 抄来的，已加警告注释。）

本 build 真实存在的警察 C2S 只有 30 个，私服**已经全部注册**，包括
`AskPoliceEffectiveExam` / `AskPoliceTakeCaseReward` / `AskPoliceTrailTeleport` /
`AskPoliceFakeFileAcceptTaskEvent` 等。

### 3.2 进入盘查的唯一入口在 C# 侧

```lua
-- 182_LX6_Manager_GamePlay_PoliceJob_PoliceJobManager.lua:795
function PoliceJobManager:EnterPoliceExamineCs(param)
    param = param:ToTable()
    self.examineMgr:EnterPoliceExamine(param)
end
```

`EnterPoliceExamineCs` 在 lua 里**只有定义、没有任何调用点**（全量 grep 确认），
调用方是原生 C#；C# 侧的实现是 Spoon 节点：

- `L50.Spoon.Nodes/L50/Spoon/SpoonRunTime/BeginPoliceExamineNode.cs`
- `.../PoliceNpcExamineNode.cs`
- `Spoon/L18/Spoon/Actions/ClientActions/BeginPoliceExamine.cs`

⇒ **盘查/逮捕的"目标 + 时机"由 Spoon 图决定，服务端插不进去。**

### 3.3 私服这一侧**已经做对**的部分

- `AgentSyncClientInfo.CanBeExaminedByPolice = true` —— 三处 NPC 生成点都已下发 ✅
- `PoliceConfig` 16 条选项的 `JobId` 都是 `[]`（**不按职业门控**），
  所以截图里那 8 个按钮**不是**被配置挡住的 ✅
- `EnterPoliceExamine(data)` 在 `customOptions` 为空时会用 `PoliceCfg` 的**默认全量列表**
  （`SetCustomTaskData` 的 `else` 分支把 `customOptions` 置 nil）⇒ 8 个按钮本来就该出现 ✅

⇒ 结论：**盘查面板本身没问题，缺的是"怎么进到那一步"。**
服务端能做的只有把已有的警察 C2S 接住（已做），让界面不卡。

### 3.4 顺带查清的两条警察 S2C（本 build 有，私服没发）

## 4. ☠️ 两个必须记住的判据（本轮新方法）

### 4.1 「某方法在本 build 存不存在」→ 查 `RPCMethodIdToName.lua`

```bash
cd Ananta.Proxy/proxy/lua
grep -oE "midToName\[<id>\] = \"[A-Za-z0-9_]+\"" RPCMethodIdToName.lua
# 无输出 = 本 build 没这个方法
```

这份 lua 的 id 与 CBT3 的 `MethodId.cs` **逐条一致**（已抽查
`SyncSpiritJobInfo=64913222` / `SyncHackerJobInfo=64189208` / `SyncHackerBatteryCurrentAndTotalCount=64742857`），
可以放心当权威。

### 4.2 「客户端实现了某 S2C 吗」→ 看 `midToExportOption`

```bash
grep -oE "midToExportOption\[<id>\] = [A-Za-z]+" RPCDeserializeAuto.lua
```

- `LuaOnly` / `LuaAndCSharp` = 客户端 lua 有函数体（**可以发**）
- 交叉验证：`SyncSpiritJobInfo`(LuaOnly) → CBT2 lua 有；`SyncHackerJobInfo`(LuaAndCSharp) → 有；
  `SyncHackerBatteryCurrentAndTotalCount`(LuaOnly) → CBT2 lua **有** ✅

☠️ **反例**：`SyncHackerBatteryCostInfo`(64748798) 也是 `LuaOnly`，但 CBT2 全量 lua 里
**只有 `midToName` 映射、没有函数体** ⇒ 发它可能触发
`attempt to call a nil value` 把整包反序列化打断。
⇒ 该包默认**关**（`spiritContent.sendHackerBatteryCostInfo`），
参考实现也没发它。

### 4.3 「处理器注册了吗」→ 启动自检

`Enabled4229938MethodIds` 是白名单，**写了 `[Handler]` 但没进白名单 = 不注册 = 客户端永远等不到回包，且服务端零报错**。

现在启动会打：

```
[ROUTER] game 注册 180 个处理器 | 骇入自检: AskHackingNpcPress=True AskHackingNpc=True AskFinishHackingKeyFrame=True AskHack=True | EnableHack=True 电池=6/6
```

（`RpcRouter.HasInvokeHandler` / `HasNotifyHandler` 是为此新增的公开方法。）

## 6. 硬边界 / 还没做

1. **盘查/逮捕的进入时机** —— 由 Spoon 图（`BeginPoliceExamineNode`）决定，
   服务端没有入口。本 build 连盘查 C2S 都删了。
2. **`SyncAgentPoliceExamData` / `SyncPoliceBeginArrest`** —— 客户端实现了，
   但没有 Spoon 触发盘查，发了也没用。要做的话得先能进盘查。
3. **骇入的"效果"** —— 私服只回成功，让客户端自己播效果。
   `SpoonGadgetManager.RegisterHackInteract` 那条链路的场景机关
   （`HackingSCIIConfig` 71 条：紧锁的大门 / 机关锁 …）仍由 Spoon 驱动。
4. **`SyncHackerBatteryCostInfo`** —— 默认关，理由见 §4.2。要开先在客户端日志里
   确认没有 `attempt to call a nil value`。
