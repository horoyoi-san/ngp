# 角色专属内容（专属技能 / 专属 App / 角色特性 / 职业 / 天赋）—— 根因分析与修复

> 日期：2026-09-23
> 触发：用户反馈「很多角色是有他的特殊内容的，比如：1、角色专属技能；2、角色专属app；3、角色特性；
> 现在的服务端完全没实现这个」。
> 用户给的例子：**塔菲**有物流接单（App 叫「蓝猫物流」）、**里希**有警察职业（可以审讯路人、召唤警车）、
> **赛默**有黑客职业（可以浏览黑客论坛、骇入车辆，有专属 App「伪人档案」）。

## 1. 取证：线格式的真值来源（**重要教训**）

`.workbuddy-ai/memory/notes/truth-source.md` 写得很清楚：

> 1. `Assembly-CSharp-FULLDUMP/`（IL2CPP 全量 dump）
> 2. `WorldDump/`
> 3. 客户端运行日志
> 4. 旁证，**不可当权威**：`Ananta.Proxy/proxy/lua/RPCSerializeAuto.lua` —— **旧 build**

本次实测确认了这条规则的**代价**。用 `Ananta.Proxy/proxy/lua/RPCSerializeAuto.lua` 比对服务端契约时：

```
CLIENT PlayerClientInfoSpirit 11 ['Spirits','InfoPokemon','AvailableSkinParts','InfoArmory',
     'ActiveSpirit','DisableBadgeInfosDict','InfoFightStyle','CommonSpiritTalentExp',
     'InfoPolice','SexTransitionLastTime','InstalledApps']
SERVER PlayerClientInfoSpirit 11 [... 'InfoFightStyle','CommonSpiritTalentExp',
     'SpiritInitTalentPointAdd','InfoPolice','SexTransitionLastTime','InstalledApps']

SERVER PlayerInfoFightStyle  2 ['FightStyleIsUnLocked','FightStyleFirstUnlockTimes']
```

看起来服务端"多字段"，其实**服务端是对的** —— `ux_rpc/ux_game_all.dump.cs` 的类定义
（TypeDefIndex 32225 / 33174）确认这两个字段都真实存在：

```csharp
public class PlayerClientInfoSpirit {
    ...
    public uint CommonSpiritTalentExp;      // 0x48
```

## 2. 逐项根因

### 2.1 角色专属技能（武学）不显示

**根因**：`RuntimePayloadFactory.MinimalPlayerInfo4229938` 里只解锁了
"loadout 实际用到"的流派：

```csharp
foreach (var styleId in ClientConfigRepository.Characters()
             .SelectMany(c => CombatCatalogRepository.Loadout(c.TemplateId).StyleByType.Values)
             .Where(styleId => styleId != 0).Distinct())
    root.InfoSpirit.InfoFightStyle.FightStyleIsUnLocked[styleId] = true;
```

而 `FightSkillConfig` 里每个角色还有**专属武学**（`SpiritId` 命中），例如：

| 武学 | `SourceDesc` | 归属 |
|---|---|---|
| `39000001 DK9 Style` | 通过【帮派纷争·龙治团】任务解锁 | 嘉姆 15020989 |
| `39000003 Righteous Reckoning` | **里希专属武学** | 里希 15021021 |
| `39000004 手铐利爪(愤怒状态)` | | 里希 15021021 |
| `39000013 Void Claw` | **`<player>`专属武学** | 主角 15020967/15020968 |
| `39000010 Gun Fu` | | 莱卡娅 15021025 |
| `39000009 Guard's Kick` | | 15021043 |

另外那批 `IsLocked=true` 的（八极拳 / 空手道 / 八卦掌 / 醉拳 / 截拳道 / 咏春拳 / 太极 / 象形拳 …）
原版靠"认可度奖励 / 任务"解锁 —— 私服没有好感度系统，所以永远是锁的。

**修复**：新增 `CollectFightStyleUnlocks`，三个来源合并：

1. loadout 用到的（原有，必须保留，否则一进世界配不出招式）；
2. **每个角色的专属武学**（`SpiritContentCatalogRepository.ExclusiveFightStyles`）；
3. **全部 `FightSkillType != 0` 的武学**（`unlockAllFightStyles`，默认开）。

同时补齐 `FightStyleFirstUnlockTimes`（**以前从来没写过**）：
修复前 `FightStyleIsUnLocked=73` 而 `FightStyleFirstUnlockTimes=50` ——
差的 23 条来自 `ApplyEconomy4229938` 的军械库武器流派解锁，那里也只写了第一个字典。
两个字典的 key 集合必须一致，否则客户端按"未获得"处理。

> `FightSkillType == 0` 的那一大批是**道具/载具伪武学**（手雷 / 滑板 / 牛奶 / 扫地机器人 /
> 躲猫猫武器 …），不是玩家武学，**不解锁**。

### 2.2 角色专属 App 永远不出现

**根因（两层）**：

**(a) `AskPhoneAppDownload` (63308287) 完全没有实现。**
`MethodId` 里有常量，但既没注册进 `Enabled4229938MethodIds`，也没有 `[Handler]`：

```bash
$ grep -rn "AskPhoneAppDownload" Ananta.Server/ --include=*.cs
Ananta.Server/ClientData/4229938/MethodId.dump.cs:505:  AskPhoneAppDownload = 63308287,   ← 只有常量
Ananta.Server/Ananta.Core/Protocol/Client4229938/MethodId.cs:540: ... const uint AskPhoneAppDownload = 63308287;
```

客户端点「下载」→ `await` 服务端回复 → 永远等不到 → 下载进度条卡住 → App 装不上。

**(b) `InstalledApps` 只回放存档。**
```csharp
root.InfoSpirit.InstalledApps = SessionState.Current.InstalledApps.ToList();
```
所以"角色专属 App"（塔菲「蓝猫物流」`22`、里希「Duty Terminal」`21` + 「伪人档案」`31`、
赛默「EonBug」`20`）永远不出现；`MobileMenuAppStoreMainConfig.IsAutoDownload` 的 10 个
预装应用也没有；`PlayerPhoneClientInfo.DownLoadAppIds` 更是从来没填过。

**修复**：
- 新增 `[Handler(MethodId.AskPhoneAppDownload, Invoke)]`，载荷与 `AskInstallMobileApp` 同形
  （`ux_game_all.dump.cs`: `UXRPCTask AskPhoneAppDownload(uint appId);`）；
- 新增 `CollectInstalledApps`：存档 ∪ 预装（10 个）∪ 每个角色的专属 App；
- `PlayerPhoneClientInfo.DownLoadAppIds` 与 `InstalledApps` 同步填充。

> ⚠️ **故意不发 `SyncPlayerMobileAppChanged` (64641811)**：客户端在 build 4229938 里
> **没有这个方法**（`script.json` 全库搜不到该名字，代理 reader 表里也没有），
> 发了也没人读。安装状态靠登录包的 `InstalledApps` / `DownLoadAppIds` 持久化。

### 2.3 角色特性

`FightSpiritCharacteristicConfig`（48 条，`FightSpiritId[]`，字段
`Id/FightSpiritId/Name/Description/Quality/Image/Notes`）**是纯客户端配置**，
客户端自己按当前角色过滤，**不需要服务端下发任何东西**。

用户"没实现"的观感，实际来自 2.2（专属 App 不出现）和 2.4（职业/天赋页全空）——
特性本身只要角色在花名册里就会显示。本次把它读进服务端只是为了后台诊断/展示。

里希的特性正好印证了用户描述：`30 治安官` / `31 征用车辆`（= 召唤警车） / `32 怪物潜能`；
赛默：`36 暗流涌动` / `37 HelloWorld` / `38 黑客车`（= 骇入车辆）；
塔菲：`14 幻速骑士` / `15 量子幽灵`。

### 2.4 职业与天赋页全空（真正的大头）

**根因**：`SpiritInfo` 里这 4 个子结构**从来没被填过**：

| 字段 | 含义 | 原来 |
|---|---|---|
| `SpiritJobInfo` | 职业（`CurrentJob` / `AvailableJobs` / `HistoryJobs`） | 空 → 所有角色都是"无业" |
| `TalentInfo` | 角色天赋（`Exp`/`Level`/`TalentPoint`/`UnlockTalentInfoDict`/`TalentTreeRecordDict`） | 空 |
| `SpiritUrbanSkill` | 都市能力（`UrbanAbilities`） | 空 |
| `SpiritBattleInfo` | `IsUniqueSkillLocked`（终结技是否锁） | 空 |

同时 `PlayerClientInfoSpirit.CommonSpiritTalentExp` / `SpiritInitTalentPointAdd` 也没设；
`SyncSpiritJobInfo` 等增量包从来没发过。

**修复**：
- `ApplySpiritContent4229938(spirit, spiritId)`：填职业 / 角色天赋 / 都市能力 / 终结技；
- `BuildSpiritJob4229938(spiritId, jobId)`：构造 `UX.Game.SpiritJob`，含职业天赋树
  （`TalentTreeConfig.JobClassId` 命中该职业大类）与存档里已加的点；
- 新增 `SyncSpiritJobInfo` 增量推送（基线项 `spiritcontent`）；
- 新增 C2S 处理器：`AskTakeJob` / `AskStartJob` / `AskFinishJob` / `AskQuitJob` /
  `AskActiveSpiritJobTalentLayer` / `AskResetSpiritJobTalent` / `AskConvertCommonSpiritTalentExp`。

## 5. 过程中踩到的坑（值得记住）

### 5.1 自己写的 bug：`JsonDocument` 被提前释放

第一版 `Records()` 返回 `IEnumerable<JsonElement>`：

```csharp
private static IEnumerable<JsonElement> Records(string root, string fileName)
{
    using var document = JsonDocument.Parse(File.ReadAllText(path));
    return records.EnumerateArray().ToArray();   // ← 返回的元素绑在已释放的 document 上
}
```

运行时报 `[SPIRITCONTENT] 载入角色专属内容失败: Cannot access a disposed object.`，
**所有表静默载入成 0 条**，面板上显示 `spirits=0 styles=0 …`。
改成回调式 `ForEachRecord(root, file, Action<JsonElement>)` 后正常。

> 教训：`JsonElement` 的生命周期绑在 `JsonDocument` 上，**不能跨出 `using` 作用域**。
> 要么在作用域内物化成 POCO，要么用回调。

### 5.2 `SpiritPanelData` 是空类（既有的无害冗余）

权威 dump（`ux_game_all.dump.cs` 与 `base/il2cpp.h` 的 `UX_Game_SpiritPanelData_Fields`）都显示
`AskAllSpiritPanelData` 的返回元素 **没有任何字段**：

```csharp
public class SpiritPanelData // TypeDefIndex: 32300
{}
```

而服务端契约里有 7 个字段（`FightSpiritId` / `UrbanAttrs` / `MaxHp` / `Dam` / `Deduct` /
`Attrs` / `NakedAttrs` / `ConsumableAttrs`）。因为 `SpiritPanelData` 是列表**唯一**的载荷，
多出来的字节属于**尾部冗余**（客户端读完列表就停），所以一直没暴露问题。
本次**未改动**它（改了要重新验证「昏迷 100%」那条线），仅记录。

### 5.3 `IsOrigin` 几乎全是 false

`TalentTreeTalentConfig` 425 条里 `IsOrigin=true` 只有 **6** 条，且全在 `99900015/99900016`
两棵树里。所以角色的职业天赋树**没有"根节点白送"**的设计，必须花天赋点。
`BuildSpiritJob4229938` 因此只在真的存在 `IsOrigin` 节点时才预置；
点数走 `spiritContent.jobTalentPoint`（默认 **35** = `TalentTreeLevelConfig` 35 级 × 1 点），
想还原原版节奏改成 `0`。

### 5.4 ☠️☠️☠️ 多态字段必须写「类型标记」而不是 `0xFF` —— 导致「进不去游戏」

**症状**（用户 2026-09-23 反馈）：能正常开游戏、点「开始」后卡加载 → 黑屏 → 过一会自动退回登录界面。

**服务端日志完全正常**（`SyncPlayerInfo body=380624b`、没有异常），**只有客户端日志有线索**：

```
[error] Lua\LuaGen\AutoGen\RPCDeserializeAuto.lua:37905:
        attempt to call local 'concrete' (a nil value)
stack traceback:
    RPCDeserializeAuto.lua:37905: in function <...:37897>      -- Auto.Dispatch[1341] 里的 concrete(reader, obj)
    RPCDeserializeAuto.lua:34962: in function 'nontrivial'     -- Auto.Reader[380] = SpiritJob
    RPCDeserializeBase.lua:175: in function 'ReadDict'         -- SpiritJobInfo.AvailableJobs
    RPCDeserializeAuto.lua:34968: in function 'nontrivial'     -- Auto.Reader[1340] = SpiritJobInfo
    RPCDeserializeAuto.lua:34925: in function 'nontrivial'     -- Auto.Reader[369]  = SpiritInfo
    RPCDeserializeBase.lua:159: in function 'ReadList7Bit'     -- PlayerClientInfoSpirit.Spirits
    ...
    RPCDeserializeAuto.lua:3295: in function 'reader'          -- midToReader[64682159] SyncPlayerInfo
```

**根因**：`SpiritJob.TalentInfo` 是**多态字段**，客户端不是用 `Base.ReadComplex` 读，而是：

```lua
Auto.Reader[380] = function (reader, obj)      -- SpiritJob
    ...
    obj.TalentInfo = Auto.Dispatch[1341](reader)   -- ← 注意不是 ReadComplex
end

Concrete[1341] = { Auto.Reader[1341], [2] = Auto.Reader[1346] }
Auto.Dispatch[1341] = function (reader)
    local tp = reader:ReadByte()
    if tp == 0 then return nil end          -- 0 = null
    local concrete = Concrete[1341][tp]     -- 0xFF(255) 查不到 → nil
    concrete(reader, obj)                   -- ← "attempt to call local 'concrete' (a nil value)"
end
```

所以这个字段前面的那个字节**不是普通的 `0xFF` 对象标记，而是类型 id**，必须命中
`Concrete[1341]` 的 key：**1 = `SpiritJobTalentInfo`，2 = `SpiritTalentInfo`**。
服务端契约用 `[UxContract(TypeMark = T)]` 指定，默认是 `0xFF` ⇒ 客户端崩。

**修复**：

```csharp
[UxContract(TypeMark = 1)]   // Concrete[1341][1] = SpiritJobTalentInfo
internal sealed class SpiritJobTalentInfo { ... }

[UxContract(TypeMark = 2)]   // Concrete[1341][2] = SpiritTalentInfo（同时兼容普通 Complex）
internal sealed class SpiritTalentInfo { ... }
```

`SpiritTalentInfo` 用 2 而不是保持 0xFF，是因为客户端 `RPCDeserializeBase.ReadComplex`
**只判 `byte ~= 0`**：

```lua
function Serializer.ReadComplex(reader, nontrivial)
    local byte = reader:ReadByte()
    if byte ~= SerializeObjectMarkNull then nontrivial(reader, obj) else return nil end
end
```

⇒ 非 0 的标记对"普通 Complex 字段"一律被接受。所以写 2 在
「普通 Complex」和「多态派发」两种读法下都正确，而 0xFF 只在后者下会崩。

> 这个机制项目里早就用过 —— `WeaponData`（`Concrete[322]`）就是 `[UxContract(TypeMark = 1)]`。

### 5.5 教训：服务端"字节数对得上"不等于客户端能读

这次的 `body=380624b` 完全正常，服务端零异常 —— 因为**服务端写的是合法字节流，
只是多态标记的取值不被客户端接受**。
排这类问题只能看**客户端日志**（`Ananta\log\Player.log`），
搜 `attempt to call local` / `lua handled error` / `LuaException`。

另外：`tools/run.sh` 被 `TaskStop` 杀掉后 **`dotnet` 子进程会存活**并锁住 `bin/` 的 DLL，
下一次 build 报 `MSB3027/MSB3021 ... 文件被".NET Host (PID)"锁定`。
必须先 `Stop-Process -Name dotnet -Force` 再 build。

### 5.6 把审计接进启动流程时又踩了三个坑（`服务端启动报错 python.exe : Traceback ...`）

审计脚本本身是好的，但**在 `Run-All.ps1` 里调用它的方式**连踩三次：

#### ① Python 输出撞上 GB2312 代码页 → `UnicodeEncodeError`

用户报错：

```
python.exe : Traceback (most recent call last):
所在位置 ...\Run-All.ps1:411 字符: 21
+         $auditOut = & $py $auditScript --strict 2>&1
+                     ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
+ CategoryInfo : NotSpecified: (Traceback (most recent call last)::String) [], RemoteException
+ FullyQualifiedErrorId : NativeCommandError
```

根因：Windows 上被 PowerShell 接住 stdout 时，Python 用
`locale.getpreferredencoding()`（中文系统 = **cp936/gb2312**）编码输出，
而脚本里有 `✅`(U+2705) / `❌`(U+274C) → **gb2312 编不了** → 崩。

复现（`[Console]::OutputEncoding` 在本机就是 `gb2312`）：

```bash
PYTHONIOENCODING=gb2312 python tools/audit_polymorphic.py --strict
# UnicodeEncodeError: 'gb2312' codec can't encode character '\u2705' in position 0
```

**修法（两层）**：

```python
for _stream in (sys.stdout, sys.stderr):
    try: _stream.reconfigure(encoding="utf-8", errors="replace")
    except Exception: pass
```
```powershell
$env:PYTHONIOENCODING = 'utf-8'      # 调用方再保一层
```
另加 `--ascii` 选项给完全不认 UTF-8 的终端。

#### ② `2>&1` + `$ErrorActionPreference='Stop'` → 原生命令的 stderr 变成**终止性错误**

PowerShell 5.1 会把原生命令写 stderr 的每一行包装成 `NativeCommandError`，
而 `Run-All.ps1` 开头就是 `$ErrorActionPreference = 'Stop'`
⇒ **python 只要往 stderr 写一个字，整个启动就挂**。

修法：调用期间临时降级，用完恢复：

```powershell
$prev = $ErrorActionPreference
try   { $ErrorActionPreference = 'Continue'; $out = & $py $script --strict 2>&1 }
finally { $ErrorActionPreference = $prev }
```

#### ③ `Start-Process -RedirectStandardOutput` 在本机直接抛异常

第一版想用 `Start-Process` 分流 stdout/stderr，结果：

```
已添加项。字典中的关键字:"http_proxy"所添加的关键字:"HTTP_PROXY"
```

`Start-Process` 内部用**大小写不敏感**的字典装环境变量，而本机同时存在
`http_proxy` / `HTTP_PROXY` / `https_proxy` / `HTTPS_PROXY` ⇒ 直接失败。
⇒ 用 `&` 调用 + 自己写文件，别碰 `Start-Process`。

#### ④ 审计工具**绝不能**成为"起不来"的原因

加了退出码约定 + 崩溃识别，保证只有"真发现问题"才阻断：

| 情况 | 退出码 | `Run-All.ps1` 行为 |
|---|---|---|
| 没问题 | 0 | 打 `OK` |
| **发现问题** | 1（输出里没有 Traceback） | `Fail`（阻止启动） |
| 脚本自己崩了 / 语法错误 | 1（输出里有 `Traceback`/`SyntaxError`/`  File "`） | 只警告 |
| 其它非 0 | ≥2 | 只警告 |
| 找不到 python / 脚本不存在 / `Ananta_SKIP_AUDIT=1` | —— | 只警告 |

**为什么要区分"1 但带 Traceback"**：Python 的默认退出码本来就是 1，
语法错误和"发现问题"都是 1 —— 只能靠输出内容分辨。

**验证**（PowerShell 侧在沙箱里无法 spawn 子进程，所以逐条单测了判定逻辑）：

```
[PASS] real findings    crashed=False expected=False
[PASS] python traceback crashed=True  expected=True
[PASS] syntax error     crashed=True  expected=True
[PASS] unicode error    crashed=True  expected=True
[PASS] clean            crashed=False expected=False

分支测试（全部 failCalled=False，即都不会阻断启动）：
  A 正常            -> [WARN] 审计进程没有启动（输出为空），跳过
  B Ananta_SKIP_AUDIT=1 -> [WARN] Ananta_SKIP_AUDIT=1，跳过审计
  C 假 python        -> [WARN] 审计进程没有启动（输出为空），跳过
```

**逃生口**：`set Ananta_SKIP_AUDIT=1` 可跳过审计。
